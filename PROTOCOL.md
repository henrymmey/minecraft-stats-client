# Client Protocol

## Protocol version

The initial protocol version is **1**.

The Minecraft mod version and Minecraft version are independent from the protocol version.

## Upload endpoint

```
POST /api/v1/ingest/batch
Authorization: Bearer <API_KEY>
Content-Type: application/json
```

## Payload rules

The client sends:

- protocol version
- mod/Minecraft version
- player UUID and username
- observed server hostname and port
- client session ID
- observation timestamp
- absolute statistic values
- idempotent event IDs

The client must not send workspace IDs as authority information.

## Absolute statistics

A statistic value represents the current observed total:

```json
{
  "key": "minecraft:killed:minecraft:zombie",
  "value": 42
}
```

The server stores the latest value and may append a history observation.

Do not send "increment by 1" semantics.

## Idempotent events

Every event has a UUID generated by the client.

If a request is retried, the same event ID is reused. The server must safely ignore an already accepted event.

## Retry policy

Retry only transient failures:

- network failures
- 408
- 429
- 5xx

Do not endlessly retry:

- 400
- 401
- 403
- 404
- unsupported protocol responses

Use exponential backoff with a bounded maximum delay.

## Local queue

The queue is bounded. Once the configured maximum is reached, the client must apply an explicit discard policy and report that state to the user.

The queue must survive normal client restarts.

## Server response

A successful response may contain:

- request ID
- server time
- next recommended upload interval

The client may use the server-provided interval but must retain a safe local minimum/maximum.

## Privacy

No chat, coordinates, screenshots, files or private messages are part of protocol v1.
